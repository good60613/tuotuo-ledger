# 第七批修改工單：桌面小工具＋載具條碼＋時間軸線

日期：2026-11-09｜接續版本：1.4.1（versionCode 7）｜目標版本：1.5（versionCode 8，Code 可建議）
存放位置：專案 `工單/第七批修改工單.md`

## 零、範圍與原則

- 這批**第一次加 Android 原生程式**（小工具必須用原生寫）。App 本體維持現在的 Capacitor 架構，**不整個移植、不重寫**。
- 不碰已定案的記帳規則與金額計算；小工具顯示的數字必須和 App 首頁**完全一致**（用同一套算法，不可另寫一份）。
- 不碰待 PK 決定的事項（圖示大改、視覺風格、F 段盤點的 10 個畫面等）。
- 建議模型：
  - A、B 段：Sonnet。
  - C 段（算數字、存給小工具）、D 段（原生小工具）、備份格式：**主對話用 Opus**，不派給 implementer。

## 一、各段工作

### A 段：時間軸那條線往下延伸（小）
- 現況：待辦與明細的時間軸，左邊的豎線到最後一筆就斷了，下面為了不讓「＋」蓋住最後一筆而留的空白，看起來像空了一塊。
- 目標：豎線繼續往下延伸，穿過那段空白，一直拉到底部操作列附近，讓空白變成時間軸的一部分。
- 適用：待辦頁（報帳、預算）、明細頁。只改畫面上的線，不影響排版高度與紀錄。
- 檢查：筆數少（貼底）與筆數多（滿版捲動）兩種情況，線都不可穿到「＋」上面或多出一截怪怪的。

### B 段：設定裡的載具號碼
- 位置：**只放在設定**，首頁與其他畫面都不加。
- 功能：輸入手機條碼載具號碼（財政部格式：斜線開頭、共 8 碼，例如 `/ABC1234`），存起來。
- 輸入檢查：格式不對就提示（請 Code 先確認財政部的最新格式規則再寫檢查）。
- 設定裡附「預覽條碼」：輸入後可以看畫出來的條碼對不對。
- 條碼格式：手機載具條碼為 Code 39（請 Code 先確認規格）。不需要連網。
- **備份**：載具號碼要不要放進「只匯出設定」與完整備份？PK 未決定，Code 先回報建議（我的建議：放進設定備份，舊檔缺欄位用空值）。動到備份格式屬於「會改使用者資料」，用 Opus。

### C 段：把小工具要顯示的數字存起來
- 小工具讀不到網頁裡的資料，所以 App 要另外存一份給它讀。
- 要存的數字：**剩餘可用、今日支出、本月支出**（皆照 App 現有規則，結算期也照現有設定），加上載具號碼。
- 更新時機：每次記帳、修改、刪除、匯入、校正後，以及打開 App 時，都要重新存一次。
- 數字來源必須和首頁共用同一個計算函式；若無法共用，請先回報原因，不要另寫一份算法。
- 請 Code 先回報：打算用哪種方式把數字交給小工具（例如 Capacitor 的偏好設定外掛，或自寫一小段橋接），白話說明優缺點。

### D 段：桌面小工具（Android 原生）
- 尺寸：**3×2**（寬 3 格、高 2 格）。
- **上半部**：手機載具條碼（用原生程式畫出 Code 39 條碼圖，條碼下方可放號碼文字）。未設定載具號碼時，上半部顯示提示「到設定輸入載具號碼」。
- **下半部**：剩餘可用（最大）；旁邊小字放今日支出、本月支出。**不放收入**（PK 決定：收入一個月就一兩筆，不常變）。
- **角落**：放拖拖記帳的 App 圖示（現在已是「被手指捏臉頰的金幣」）。若有去背版就用去背版；沒有的話先用現有圖切切看，不好看就回報，由 PK 提供。
- **點擊**：點小工具任何地方，都打開拖拖記帳**首頁**。不做全螢幕大條碼（PK 決定；日後有店掃不到再加回）。
- 外觀：深色底、圓角，比照 PK 現在桌面上別的記帳 App 小工具的質感；字級與間距放設定檔，方便微調。
- 已知限制（請 Code 在回報裡確認並白話說明）：小工具不能自動調亮螢幕；條碼較小，部分店家掃描槍可能掃不到。
- 更新頻率：Android 對小工具的自動更新有限制，請 Code 說明小工具「何時會更新」，並確保記帳後小工具會跟著更新。

### E 段：檢查與打包
- 型別檢查、自動測試。
- 版本 1.5（versionCode 8，上一版為 7），同金鑰簽章，applicationId `tw.pk.ledger` **不可改**。
- 確認 `cap sync`（把網頁內容同步到 Android 專案）**不會把自寫的小工具原生程式洗掉**；若有風險，先回報。
- 確認舊的打包流程（`打包APK.bat`）仍可用，打包環境的老問題（AVG、中文路徑、同步軟體鎖檔）照 `文件/更新流程.md` 處理。
- 在 `文件/` 補更新紀錄；小工具的做法、資料怎麼交給它、日後怎麼改，另寫一份短說明 `文件/小工具說明.md`。

## 二、可能出事（Code 要特別檢查）

- 小工具的數字和首頁對不上（程式問題或構造問題，最重要）。
- 記帳後小工具沒更新，或更新很慢。
- 沒設定載具號碼時，小工具上半部壞掉或空白。
- 載具號碼格式錯誤時，畫出掃不出的條碼。
- 加入原生程式後，打包失敗或 `cap sync` 洗掉小工具程式。
- 小工具顯示金額，桌面誰都看得到：PK 若在意隱私，可日後加「隱藏金額」選項（本批不做，Code 先在回報提一句即可）。

## 三、給 Code 的固定要求

- 全程繁體中文白話；專有名詞第一次出現附一句解釋。
- 出錯先說嚴不嚴重。
- 回報每個問題標：程式問題／構造或架構問題／使用問題。
- 省 token：不重複驗證、不讀用不到的大檔。
- 每段做完 commit。
- 可調數值放 `src/config.ts`（小工具的原生側數值放對應設定檔，並在說明裡寫清楚位置）。
- 需要 PK 操作時，一次只給一步。
- **先列分段計畫與疑問，等 PK 確認才施工。** C 段「怎麼把數字交給小工具」的做法，先回報再做。
