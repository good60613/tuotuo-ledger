## 第一段：讀檔失敗保護＋自動留底（審查報告的嚴重項）

### 問題

App 打開時讀不到手機上的資料，畫面會換成範例資料；之後只要再動任何一筆，就把範例資料存進去，真帳本被整個取代，且沒有自動留底。

### 規則（PK 決定）

**A. 讀檔失敗就不准存檔**
- 開啟時若讀取或資料升級失敗：進入「唯讀保護狀態」，**絕不寫入、絕不載入範例資料取代**。
- 畫面用白話顯示：資料讀取失敗、目前不會存任何變更；提供選項：重試、從自動留底還原、從備份檔匯入。
- 唯讀保護期間，所有會寫入的操作（記帳、拖曳、設定變更）都要擋下並說明，不可靜默失敗。
- 要區分「讀取失敗」與「第一次使用、本來就沒有資料」：後者才可以走新手或範例流程。
- 若偵測到「資料版本比 App 還新」（例如裝到舊版 APK），也走唯讀保護，並提示更新 App，不可降版覆蓋。

**B. 自動留底**
- 資料升級（schema 版本變更）之前，先把舊資料原樣留一份，升級失敗可還原。
- 日常自動留底：每天第一次開啟 App 時，留一份目前資料快照；只保留最近幾份（份數放 `src/config.ts`，建議 7 份，由 Code 評估儲存空間後決定並回報）。
- 留底存在 App 自己的儲存空間，不依賴 PK 手動匯出；不可與主資料同一個寫入動作，避免一起壞掉。
- 設定頁（資料備份區）新增「自動留底」入口：列出每份的日期與帳戶、紀錄筆數，可選一份還原；還原前二次確認，並先把「目前資料」再留一份，避免還原也無法反悔。
- 清空資料、載入範例、匯入備份（取代）這三種會蓋掉資料的操作，執行前都自動留一份。

### 驗證（自動測試，全過才往下）

1. 模擬讀取失敗：App 進入唯讀保護，不載入範例、不寫入；嘗試記帳被擋。
2. 模擬「第一次使用」：正常進入，不誤判為失敗。
3. 模擬升級中途出錯：舊資料仍在，可從留底還原。
4. 模擬資料版本比 App 新：進唯讀保護，不降版。
5. 還原留底後，帳戶餘額、剩餘可用、本月支出與留底當時一致。
6. 蓋掉資料的三種操作，執行前都產生留底。

## 第二段：刪除帳戶時，紀錄只能移到同種類帳戶

### 規則（PK 決定）

- 刪除有紀錄的帳戶，選項維持：**取消、移到別的帳戶、連同紀錄刪除**（連同刪除維持二次確認）。
- 「移到別的帳戶」只列**同種類**的帳戶：一般帳戶只能移到一般帳戶；悠遊卡、電子錢包、投資、儲蓄各自只能移到同種類。
- 沒有可移的同種類帳戶時，隱藏或停用「移到別處」，並說明原因（白話一行），只剩取消與連同刪除。
- 不可因為跨種類移動而讓本月支出、剩餘可用莫名改變。

### 驗證

1. 刪現金：可移的對象只有其他一般帳戶，不出現悠遊卡。
2. 只剩一個一般帳戶時刪它：「移到別處」不可選。
3. 同種類移動後：本月支出、剩餘可用、各帳戶餘額數字與移動前一致（扣除被刪帳戶本身）。

## 第三段：朋友付還款，限制可選帳戶（選 B）

### 規則（PK 決定）

- 還「朋友付」時，可選的還款帳戶只有：**一般帳戶、悠遊卡、電子錢包**。
- **儲蓄、投資、其他不可選**。還款畫面不列出它們，並加一行提示：「這個帳戶不能還款，請先轉到一般帳戶」。
- 原因：這三種帳戶的錢轉出是轉帳，不算支出，會造成朋友付永遠不被算成支出。
- 「我先付」算法不變；收款帳戶限制不在本批範圍。
- 已經結案的舊資料不改。已存在、未結案的朋友付，照新限制還款即可。

### 驗證

1. 還款畫面不出現儲蓄、投資、其他帳戶。
2. 用一般帳戶還：支出在還款當天算 600，帳戶少 600。
3. 用悠遊卡或電子錢包還：與補強批驗證一致，不重複算。
4. 先把儲蓄轉到一般帳戶（轉帳不算支出），再用一般帳戶還：支出只算一次 600。
